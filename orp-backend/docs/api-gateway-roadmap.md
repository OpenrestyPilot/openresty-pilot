# API 网关能力路线图

更新日期：2026-10-19。

## 定位

当前项目首先是 OpenResty 配置控制面，已有 HTTP/Stream 监听、上游、路由、IP allow/deny、配置校验与发布能力。它还不是完整的 API 管理网关：API 调用方身份、凭证生命周期、可执行的 API 访问策略、消费者配额及端到端流量验收尚未闭环。以下路线按依赖顺序推进；每阶段须同时完成配置面、数据面渲染、发布验证和运维文档，才可标为完成。

## 当前实现边界与技术决策

- NGINX 原生 `limit_req` 首期使用 `$binary_remote_addr` 作为 key，共享区按监听和路由 ID 唯一命名；速率限制是单节点 worker 共享，不是跨节点全局配额。
- 速率限定义范围为 1–100000 请求/秒，burst 为 0–1000000；启用时必须显式提供整数值。初期不支持按任意请求头限速，避免信任客户端可伪造字段。
- 当前 Quickstart HTTP 监听/Location 路由抽屉通过 `/api/orp/http-listeners` 读写 `orp_resource`，与候选/发布器读取的资源模型一致；路由限流设置沿这条链路进入候选快照。另有旧 `/api/centers/{centerID}/http-servers` 与 `http_location` 接口，仍是独立兼容面，本轮没有把旧模型迁移或声明为同步。阶段 0 的验收以当前 Quickstart 管理路径及真实目标节点为准。
- API Key/JWT/OAuth2 不是同一阶段的替代选项。当前管理端为 Consumer 密钥保存 SHA-256 哈希，只在签发/轮换响应显示完整密钥一次；轮换保留旧密钥，需确认切换后单独撤销。`lookupAPIKey` 已校验格式、哈希、调用方状态、密钥状态和过期时间，但目前尚未被代理数据面调用；不存在已上线的 API Key 请求认证或身份传递契约。不得把客户端任意 header 当认证身份。
- 用户已明确不需要导入项目之前的旧业务数据；本路线仅针对当前项目的新模型和新部署，不把旧库迁移列为网关完成条件。

## 本轮实施记录

发布器在 HTTP 上下文生成路由专属 `limit_req_zone`，在 Location 中生成 `limit_req`；当前路由抽屉可编辑速率、突发额度和 `nodelay`，新建/历史路由默认关闭。允许方法列表在不为空时渲染为 `limit_except ... { deny all; }`；空列表兼容既有行为。后端校验允许方法枚举和限流参数范围。限流按 `$binary_remote_addr` 计数，只在单节点内共享，不提供跨节点全局配额。代码已本地构建；真实目标 `nginx -t` 和 GET/POST/超限请求行为验收未完成，阶段 0 仍为进行中。

Consumer/API Key 管理面已经实现：Consumer 分页 CRUD、停用时事务性撤销有效密钥、密钥元数据列表、一次性签发、保留旧密钥的替代签发/轮换、显式撤销和审计。数据库仅保存 SHA-256 哈希及短前缀；审计及列表不含密钥。管理 API OpenAPI TS 与 `public/swagger/openapi.json` 已同步。Go 构建与 OpenAPI 已记录 operation 的路由存在性检查通过。尚未验证真实 MySQL migration/API 生命周期，也未把 lookup helper 接入 HTTP 代理请求；因此阶段 1 只完成管理面凭据生命周期，不宣称 API Key 认证已上线。下一步是代理端受保护路由策略、认证失败 401、可信身份注入与上游身份头清理，并用实际请求验收轮换和撤销的即时效果。
