# ADR-0015：配置候选快照与持久化校验任务

## 状态

已接受（目标架构）；当前已实现持久化候选、冻结 Diff、中心并发策略和受限目标校验，通用节点覆盖与生产验收仍未完成，见“实现状态”。

## 决策

- 候选是独立、不可变的 MySQL 记录，保存中心、创建者、配置快照及摘要、Diff 基线版本/摘要、精确目标节点快照、生成时间和归档状态。候选生成和读取草稿使用同一个 MySQL `REPEATABLE READ` 一致性事务；若任一输入读取失败则回滚，不写入候选。
- 候选生成事务内同时写入首个校验尝试及逐节点待验证结果。Diff 基于冻结快照立即计算；每次重试写新尝试，不覆盖历史结果。
- MySQL 是候选、调度和审计证据唯一权威。验证任务与逐节点状态持久化到 MySQL；控制面后台 worker 使用短事务领取工作、租约与超时回收，节点校验在事务外执行。Redis 不可用不影响任务正确性。
- 每中心配置最大在途校验数。调度器在有待处理任务的候选之间轮转，每轮每个候选至多派发一个节点任务；候选配置只能下调自己的并发，不得突破中心上限。
- 任一目标校验失败后暂停该尝试尚未派发的节点；在途任务完成并落库后，等待具备中心配置编辑权限的操作者继续或停止。进程重启后租约过期任务标为结果未知，不自动重试；操作者可逐节点重试。
- 候选校验默认不触发发布。创建人可显式选择“所有冻结目标校验成功后自动发起发布”，也可在成功后由具备目标中心 `orp:publish` 权限的操作者手动触发；自动路径同样重新校验权限、当前配置摘要、目标身份和冻结基线。两种路径复用既有固定批次执行器及其 Canary 门槛；校验失败、暂停、停止或结果未知均不得自动发布。
- 节点操作只允许部署提供的固定暂存/校验脚本和参数白名单。校验必须在非活动目录运行目标节点 `nginx -t`；不得调用会激活配置、Control API reload 或 restart 的部署脚本。当前已提供 Quickstart 与固定 Agent 两种受限校验适配器，其他拓扑仍需各自的安全适配器。
- 首期候选只归档/取消归档，不硬删除；创建、重试、继续/停止、归档操作及逐节点结果记入审计。

## 后果

- MySQL 行锁和租约提供多控制面实例间的唯一任务领取与故障恢复，不以进程内 goroutine 状态作为事实源。
- 候选快照必须以确定性渲染摘要及目标校验结果为证据；不得把“候选生成成功”宣称为“目标校验通过”或“节点已激活”。
- 系统没有独立人工审批门禁；发布需要人工确认，除非创建时已显式选择受控的校验成功后自动衔接。

## 实现状态（2026-10-15）

当前另有独立异步候选后端切片：V44 创建候选、attempt、逐节点 job 与中心策略表；候选创建从单个 REPEATABLE READ 事务读取资源、singletons 和准确节点集合，原子写入快照、首个 attempt/job 和审计；候选读取按中心范围过滤，操作支持归档/恢复、失败或未知节点重试、暂停后的继续/停止。lease worker 具有中心并发门限、中心级持久轮转游标、短事务租约领取与超时结果未知回收逻辑。前端提供候选列表、详情、Diff、任务与中心校验策略管理界面。

目标节点校验现已接入两个受限 adapter：固定 Quickstart 三节点在各自容器的候选目录暂存并运行 `nginx -t`；异地节点必须存在冻结快照中的 Agent 身份，控制面验证最近心跳及已登记凭据后，派发固定 `validate` 操作和不可变制品，Agent 仅在固定候选路径暂存并运行 `nginx -t`。Agent 任务的 DB 操作编码与旧发布候选 ID 空间分离；返回给 Agent 的操作仍是 allowlist 中的 `validate`，不含命令或路径。二者均不切换 `active`、不 reload，也不激活配置。候选渲染内容会与持久化摘要核对后才可派发。

候选冻结时逐目标节点记录当时最后一次成功发布的版本 UUID 和摘要，并复用发布流程的 `semanticReleaseDiff` 与 `publishTextDiff` 保存语义差异、文本差异及增删行数。创建响应与详情读取均返回这组冻结证据；后续发布发生时不会重算历史候选的基线。首次发布节点的基线版本和摘要为空，Diff 从空配置计算。

每中心策略通过 `GET/PUT /api/orp/validation-centers/{centerId}/policy` 读取和更新。读取需中心 `orp:read`，更新需中心 `orp:config:write`，范围为 1 到 32 并记录审计。候选 attempt 的 concurrency 不得超过中心 `maxInflight`；重试在策略降低后会按新上限收敛。worker 领取时在中心策略行锁下检查全中心运行数，确保多个候选及多个控制面实例合计不突破中心上限。调低策略不会取消已运行的任务，只会暂停后续领取，直到活动数低于新值。

尚未形成通用环境适配：非 Quickstart 且无 Agent 的节点、root-master/helper profile、节点原生指令及其他拓扑会以明确失败结束；Agent 目标还要求其自身已正确部署非 root release profile。`adapter_required` 保留给服务未配置 executor 的部署状态，不表示校验通过。V44 候选仍与旧 publish-candidate 表分离；校验默认只生成校验证据，只有创建时显式启用自动发布，或操作员通过 `orp:publish` 权限手动确认，才会创建关联的旧发布候选和批次。

既有 `POST /api/orp/publish/precheck` 仍是独立的同步预检路径，固定非 root Agent 也可参与该发布链路。V44 候选与旧发布表分离，通过 V49 关联并实现默认关闭的校验后自动发布选项及显式手动发布入口；自动衔接以数据库租约保证多实例至多创建一个批次。Agent 发布只支持固定非 root profile。V47 为 Agent publish task 增加到发布批次项的持久化关联；重启后未领取任务可安全取消，已明确成功的 task 可核对为成功，结果未知的批次进入 `recovery_required`。人工续跑接口要求操作员逐节点提交观察 UUID，并派发固定、只读的 Agent `probe` 或调用本地固定版本探针；服务端只允许核对冻结候选 UUID 或成功预检时记录的基线 UUID。未知/失败项即使确认仍在基线也只会跳过；只有原未开始目标在冻结基线、目标身份不变且候选仍校验有效时才重新入队。任何不匹配、缺失基线或拓扑改变均拒绝续跑。Agent Canary 和中央历史快照回滚通过固定 `probe`/`validate`/`publish` 任务链执行；root-master/helper 等其他运行 profile 仍未实现。

因此，本 ADR 描述的通用目标能力仍未全部实现；已完成的受限校验范围也与 Compose MVP 的发布能力属于不同阶段。任何文档描述当前服务时应以 `docs/frontend-backend-migration-status.md` 的实现证据为准。
