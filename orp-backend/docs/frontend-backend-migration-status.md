# Go 控制面后端功能盘点

更新日期：2026-10-08。

## 结论

后端的本地 Compose 演示闭环已覆盖资源管理、认证/RBAC、配置渲染与校验、三节点分批发布、回滚、观测、日志和审计，不能据此判断“后端全部完善”。生产节点发布、ADR-0015 的异步候选工作流、运行时完整 OpenAPI 契约、生产日志运维和部分 NGINX 配置能力仍有明确缺口。下面状态以 Go 路由和处理器、迁移、模块 README 及既有验证记录为依据；“已接入”表示代码/本地环境已验证，不代表生产部署验收。

## 功能状态总览

| 功能域 | 状态 | 现状与边界 |
|---|---|---|
| 登录与个人资料 | 已实现 | MySQL 账号、签名令牌、刷新/登出、bcrypt、OTP、个人资料与密码操作。 |
| 角色与权限 | 权限、审计和中心范围已接入 | 超级管理员独占账号/角色管理；内置平台管理员、配置编辑员、发布操作员、审计只读和敏感数据审计员职责分开。账号、角色、权限及密码重置变更事务性写入审计。自定义角色可配置中心范围，后端对资源、旧接口、发布节点、日志及审计记录执行范围校验；详见 [`rbac-role-model.md`](rbac-role-model.md)。 |
| 配置资源管理 | 已实现（模型覆盖范围内） | Center、节点、HTTP/Stream、TLS、DNS、策略、系统配置、字典/配置分组及审计 CRUD；旧数据迁移目前只同步 Center，其他 UUID 资源没有系统迁移。 |
| 密钥与敏感字段 | 已实现（当前部署边界） | 敏感配置、证书私钥和 OTP 等使用 AES-GCM；密钥须由部署安全提供，需按实际环境验证备份、轮换和访问策略。 |
| 配置渲染 | 局部实现 | 确定性渲染覆盖已建模的 HTTP/Stream 资源、证书、DNS、错误页和部分策略；并非通用 NGINX 语法树。节点级原生指令、主动健康检查、`slow_start` 等不支持项会被拒绝。 |
| 发布预检 | 已实现（本地节点） | 同步冻结快照，逐目标 Compose 节点运行真实 `nginx -t`，保存语义 Diff、文本 Diff 和结果。没有 ADR-0015 中自动异步校验、租约、公平调度、失败后继续/停止节点队列的工作流。 |
| 发布与回滚 | 已实现（仅三固定 Compose 节点） | 候选活动路径切换、reload、工作进程版本探针、权重批次/观察期、中止、失败停止后续节点及单节点历史快照回滚。目标识别硬编码为 east-1/2/3；其余地址会拒绝。不是通用生产发布通道。 |
| 进程中断恢复 | 有限恢复 | 启动时对执行中的发布项进行版本探针核对；已确认加载则登记成功，未开始项中止，无法确认标失败并需重新预检。没有持久化 worker 租约或安全自动续跑。 |
| 节点 Agent | 局部实现 | 独立 mTLS listener 接入心跳、任务领取、结果回报；超级管理员可登记证书指纹并手动派发固定 reload。证书签发/轮换、Agent 状态 UI、制品传输/校验和发布批次编排尚未接入。需配置独立 HTTPS 地址、服务器证书/私钥与客户端 CA。 |
| 监控与大盘 | 已实现（本地数据源） | 节点指标、健康样本、延迟历史、大盘 REST/SSE；Redis 可用于快照缓存和生成队列，不是配置权威。生产容量、告警 SLO 和高可用尚未验收。 |
| 日志 | 已实现（本地链路） | Filebeat→Kafka→MySQL 消费持久化、节点/类型关联、访问指标、鉴权实时日志 SSE 和本地日志回退。生产 Kafka 扩容、保留、归档、积压恢复需要单独规划与验收。 |
| GeoIP | 已实现但缺真实数据验收 | 有受管 City `.mmdb` 导入/替换及状态接口；未导入授权数据库时来源地图不构成真实功能验收。 |
| TLS 到期告警 | 已实现（代码路径） | 告警渠道、规则、检查、投递记录及飞书消息实现；不同生产渠道凭据、网络、重试和告警验收须按环境完成。 |
| OpenAPI | 路径覆盖，payload 不完整 | 自动检查 Go ServeMux 路由映射及前端 OpenAPI 规范结构；尚未覆盖全部业务响应 schema 的准确性和运行时响应契约。 |

## 已接入真实服务

- 独立项目 `orp-frontend/` 使用 Vue/Vben 前端，开发服务器将 `/api/**` 代理到本地 Go 控制面；Nitro Mock 已关闭。
- 根 Go 控制面整理为独立项目 `orp-backend/`；导入目录 `app-epvimbagnu2p/` 保留为历史参考，不属于当前三个项目。
- 登录、登出、签名令牌、管理员初始化、用户与角色、读写权限、个人资料、密码修改及 OTP 使用 MySQL 存储。密码采用 bcrypt；证书私钥、敏感配置值与 OTP 密钥采用 AES-GCM 加密。
- Center、节点、HTTP 监听、Stream 服务、证书、DNS、Upstream、IP 组、系统配置与配置分组支持持久化增删改查，并记录变更审计。现有旧库 Center 会映射到新控制台，Center 新增、修改和删除会同步到旧表。
- HTTP/Stream 全局指令与日志格式、证书到期统计、配置项明文授权读取、分组排序和批量移动已接入。
- HTTP 错误页面已接入 HTTP 全局默认与单站点覆盖：支持状态码默认页和 Content-Type 专用页，保存时校验状态码、媒体类型与 1 MB 正文上限；发布渲染生成内容类型 map、受控 internal location 和候选页面文件，单站点设置按键覆盖全局值，其他配置继续继承。对应 Go 接口已列入 OpenAPI。
- 本地 `openresty-east-1`、`openresty-east-2`、`openresty-east-3` 已接入真实发布：MySQL 冻结候选与节点清单、分别在容器内运行 `nginx -t`、切换各自活动制品、reload，并通过各自工作进程的版本探针确认加载；失败会尝试恢复原版本。配置比对、待发布汇总、批次进度、历史查询与历史快照回滚已接入。
- 权重分批按节点权重升序执行；首批可进入观察期，支持自动到期、立即推进与中止未下发节点。运行中节点失败时停止后续批次。
- 节点定时探测持久化延迟与健康状态；节点指标读取 Docker 和 NGINX 状态以及访问日志。节点运行状态操作实际启动、暂停或停止本地容器，再核对目标状态。
- 本地节点、HTTP 监听和 Stream 服务日志按目标读取；HTTP 访问日志驱动大盘请求量、状态码、延迟、带宽、趋势与排行。六张地理大屏通过鉴权 SSE 使用真实大盘数据；配置 GeoIP City `.mmdb` 后按客户端公网 IP 聚合来源点，并仅连向录入坐标的中心。大屏页面切换时暂停 SSE，避免标签缓存留下重复长连接。
- 三个本地 OpenResty 节点各由 Filebeat 采集 access/error 文件日志，发布到 `ORP_KAFKA_BOOTSTRAP_SERVERS` 配置的 Kafka（当前本地地址 `127.0.0.1:9092`、主题 `orp-access-logs`）；Go 控制面按消费者组持久化、去重并解析访问记录。大盘访问指标优先使用持久化 Kafka 数据，实时日志页通过鉴权 SSE 推送新日志；没有 Kafka 记录时保留本地日志读取回退。
- Upstream 的普通 Hash 与一致性 Hash 策略已增加显式变量键，HTTP/Stream 渲染均生成对应指令；非法表达式被预检拒绝。
- Stream 上的 `ip_hash` 映射为 `hash $remote_addr`，提供同客户端地址粘性选择；HTTP 仍使用原生 `ip_hash`。
- Stream 服务可组合多个“上游组:目标端口”：渲染器展开组内节点，生成服务专属上游并代理到它。单组保留组级负载策略；多组采用轮询，其他组策略或原生指令会被预检拒绝。

| 跨进程继续执行 | 重启时逐节点探针核对：已确认加载的项恢复为成功，未开始的排队项中止，无法确认的项标为未知并要求重新预检；不会盲目重放 | 加入带租约的执行所有权和操作员确认后的安全续跑 |
