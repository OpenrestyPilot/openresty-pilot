# Go 控制面后端功能盘点

更新日期：2026-10-19。

## 结论

本地 Compose 演示闭环已覆盖资源管理、认证/RBAC、配置渲染与校验、三节点分批发布、回滚、观测、日志和审计；异步候选及策略管理界面、受限 Agent Canary/历史回滚/人工恢复接口和完整成功响应 schema 已接入。2026-10-18 在独立服务器部署非 root Agent 节点，验证了远端候选 `nginx -t`、批次发布和中央历史回滚；该次为单目标验证，没有覆盖多节点 Canary 观察门槛或重启恢复。随后在 `8.137.113.9` 部署公网 IP 验收服务，通过现有 18443 TLS 网关完成真实外部请求，确认节点收到网关转发的公网客户端 IP，City MMDB 可解析国家、城市和坐标。用户报告该请求未驱动控制面大盘、实时日志和大屏。复核发现该独立服务器原先没有 Kafka/Filebeat，控制面 Kafka bootstrap 配置为空，访问记录只写在节点本地文件。为修复链路，本轮在服务器增加了回环 Kafka broker、设置控制面 Kafka 地址并启动 consumer；但本轮尝试增加 Filebeat/调整节点日志容器时出现节点容器重启和端口占用，已将公网检查服务恢复为稳定运行，尚未验证 Filebeat 发布、MySQL 入库、GeoIP 聚合 API、日志 SSE 或大屏 SSE。因此公网请求到三个界面的端到端问题仍未解决，不能宣称已联动。配置比对已分开展示审计操作数、发布后的资源净差异数和渲染文本增删行数。旧系统数据迁移不属于本项目发布完成条件：项目尚未正式发布，既有导入代码仅作为可选兼容路径保留，不要求为历史旧库补齐映射。当前主要未闭环项是 root-master/helper 与其他拓扑支持、多节点 Canary 观察门槛、Agent/控制面重启恢复、独立部署的 Filebeat→Kafka→MySQL→GeoIP/API/SSE 日志链路、生产 Kafka 运维和全量运行时 OpenAPI 契约验收。2026-10-18 本地 OpenAPI 静态检查与服务可用性检查通过；独立公网部署已在 TCP 18443/18444 完成外部连通、控制台健康、大屏页面和登录配置脱敏检查。该部署验证基础安装与访问，不代表已完成生产级安全、容量、高可用或真实业务验收。

用户已启动“完整 API 网关能力”补齐工作。阶段与验收标准见 [`api-gateway-roadmap.md`](api-gateway-roadmap.md)。2026-10-19 本轮把允许 HTTP 方法与路由级限流接入 Quickstart 路由抽屉、前端类型和 OpenAPI 契约；配置由 `/api/orp/http-listeners` 保存至 `orp_resource`，进入候选/发布器使用的同一资源模型。后端校验方法枚举及限流范围，渲染 `limit_except`、`limit_req_zone` 与 `limit_req`；限流默认关闭以维持现有行为。本地构建通过；目标 `nginx -t` 和真实 GET/POST/超限请求行为尚未验收，旧 `/api/centers/{centerID}/http-servers` 表模型仍为独立兼容面。完整 API 网关仍未完成。

2026-10-19 同一轮还完成了 API Consumer/API Key **管理面**凭据生命周期：V51 创建独立 Consumer 与 key 表；控制面提供 Consumer CRUD、分页 key 元数据查询、一次性签发、轮换和撤销。完整密钥只返回给签发/轮换调用一次，数据库只保留 SHA-256 哈希，审计仅保留不含密钥的元数据；停用 Consumer 会在同一事务中撤销有效 key。OpenAPI TS 与静态 Swagger JSON 已同步。`lookupAPIKey` 目前只是未接入代理请求链路的后端 helper，因此无效或撤销 key 尚不会通过真实网关请求返回 401；匿名/受保护路由策略、身份注入、上游伪造身份头清理、消费者授权/配额以及真实 MySQL 生命周期验证仍未完成。不能将阶段 1 或完整 API 网关标为完成。

## 已接入真实服务

- 独立项目 `orp-frontend/` 使用 Vue/Vben 前端，开发服务器将 `/api/**` 代理到本地 Go 控制面；Nitro Mock 已关闭。
- 根 Go 控制面整理为独立项目 `orp-backend/`；导入目录 `app-epvimbagnu2p/` 保留为历史参考，不属于当前三个项目。
- 登录、登出、签名令牌、管理员初始化、用户与角色、读写权限、个人资料、密码修改及 OTP 使用 MySQL 存储。密码采用 bcrypt；证书私钥、敏感配置值与 OTP 密钥采用 AES-GCM 加密。
- Center、节点、HTTP 监听、Stream 服务、证书、DNS、Upstream、IP 组、系统配置与配置分组支持持久化增删改查，并记录变更审计。控制面启动不再自动导入旧业务数据；新建中心仍为兼容现存旧路由而写入 UUID 镜像记录。
- HTTP/Stream 全局指令与日志格式、证书到期统计、配置项明文授权读取、分组排序和批量移动已接入。
- HTTP 错误页面已接入 HTTP 全局默认与单站点覆盖：支持状态码默认页和 Content-Type 专用页，保存时校验状态码、媒体类型与 1 MB 正文上限；发布渲染生成内容类型 map、受控 internal location 和候选页面文件，单站点设置按键覆盖全局值，其他配置继续继承。对应 Go 接口已列入 OpenAPI。
- 本地 `openresty-east-1`、`openresty-east-2`、`openresty-east-3` 已接入真实发布：MySQL 冻结候选与节点清单、分别在容器内运行 `nginx -t`、切换各自活动制品、reload，并通过各自工作进程的版本探针确认加载；失败会尝试恢复原版本。配置比对、待发布汇总、批次进度、历史查询与历史快照回滚已接入。
- 权重分批按节点权重升序执行；首批可进入观察期，支持自动到期、立即推进与中止未下发节点。运行中节点失败时停止后续批次。
- 节点定时探测持久化延迟与健康状态；节点指标读取 Docker 和 NGINX 状态以及访问日志。节点运行状态操作实际启动、暂停或停止本地容器，再核对目标状态。
- 节点实例指标抽屉使用鉴权 SSE，建立连接后立即推送，之后每秒推送一个指标快照；关闭抽屉时中止连接，断线后退避重连。Kafka 入库场景的请求量/错误率/带宽使用 MySQL 时间范围聚合，避免每秒重扫全天事件；无持久化事件时仍保留本地日志回退读取。
- 本地节点、HTTP 监听和 Stream 服务日志按目标读取；HTTP 访问日志驱动大盘请求量、状态码、延迟、带宽、趋势与排行。大屏展示页为卡片目录，包含世界地图及 23 个行政区各自的 2D/3D 页面，支持搜索、亮暗主题和行政区下钻；页面通过鉴权 SSE 使用真实大盘数据。配置 GeoIP City `.mmdb` 后按客户端公网 IP 聚合来源点，并仅连向录入坐标的中心。大屏页面切换时暂停 SSE，避免标签缓存留下重复长连接。
- 三个本地 OpenResty 节点各由 Filebeat 采集 access/error 文件日志，发布到 `ORP_KAFKA_BOOTSTRAP_SERVERS` 配置的 Kafka（当前本地地址 `127.0.0.1:9092`、主题 `orp-access-logs`）；Go 控制面按消费者组持久化、去重并解析访问记录。大盘访问指标优先使用持久化 Kafka 数据，实时日志页通过鉴权 SSE 推送新日志；没有 Kafka 记录时保留本地日志读取回退。
- Upstream 的普通 Hash 与一致性 Hash 策略已增加显式变量键，HTTP/Stream 渲染均生成对应指令；非法表达式被预检拒绝。
- Stream 上的 `ip_hash` 映射为 `hash $remote_addr`，提供同客户端地址粘性选择；HTTP 仍使用原生 `ip_hash`。
- Stream 服务可组合多个“上游组:目标端口”：渲染器展开组内节点，生成服务专属上游并代理到它。单组保留组级负载策略；多组采用轮询，其他组策略或原生指令会被预检拒绝。
