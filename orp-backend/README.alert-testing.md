# 告警通知本地验证

该功能支持通用 JSON Webhook 和飞书自定义机器人。TLS 到期提醒按证书关联通道推送，发送记录展示 HTTP 状态和失败原因。地址及签名密钥加密存储；Webhook 签名通过 `X-ORP-Timestamp` 与 `X-ORP-Signature: sha256=<HMAC-SHA256>` 传递，飞书按机器人签名规则生成 `timestamp` / `sign`。

## 准备演示数据

先在独立的 `orp-quickstart` 项目运行 `./scripts/start-source.sh` 启动源码环境，再在 monorepo 根目录执行以下命令。脚本会复用当前环境配置和本地密钥，不会在终端显示密码或密钥。它会应用缺少的数据库迁移，并幂等地创建一张 10 天后到期的自签名演示证书、一个指向本地接收器的 Webhook、一个待配置的飞书通道占位，以及已关联的 30 天提醒规则。两个通道初始均停用，不会自动外发。

```bash
OPENRESTY_ENV_FILE=../orp-quickstart/.env ./orp-backend/scripts/seed-alert-demo.sh
```

## 测试通用 Webhook 和 TLS 到期提醒

在一个终端启动本地接收器：

```bash
go run ./cmd/alert-test-sink
```

然后登录 ORP，打开“告警通知”：

1. 在推送通道中编辑“本地 Webhook 演示”，保存后启用。
2. 使用“测试”确认接收器返回 HTTP 200；接收器终端会显示消息 JSON。
3. 找到“演示 TLS 到期提醒证书”，确认已关联本地 Webhook 且阈值为 30 天。
4. 点击“立即检查”；发送历史应出现 TLS 到期提醒，接收器也会输出同一事件。
5. 再次立即检查时，当日同证书、同到期日、同通道会去重；发送历史不会重复增加。

接收器健康检查：`curl http://127.0.0.1:8099/health`。

## 测试飞书文本和消息卡片

编辑“飞书机器人演示（待配置）”，填入飞书自定义机器人的 Webhook 地址，在“飞书消息格式”中选择“交互式消息卡片”或“普通文本”；如机器人启用了签名校验，同时填写签名密钥并启用通道。卡片按到期紧急程度使用蓝/橙/红色标题栏，并显示证书、域名、到期日期及剩余天数。点击“测试”可以确认机器人接收情况；飞书返回的业务错误也会作为发送失败记录展示。

演示证书是随机生成的自签名证书，只用于到期提醒数据测试，请勿用于实际流量。
